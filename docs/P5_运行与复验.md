# P5 官方评测：运行与复验

120场景续验入口已扩展，以下旧40核心/200冒烟数字仅描述首轮历史批次。
当前默认开发集为 **120来源场景＋40原P5场景＋25回答/条件回归＋9条实际失败消息回归**，合计194个非冒烟场景，
`--repetitions 3 --smoke` 为582次核心运行＋200次开发冒烟，不能把782次运行当782个独立风险样本。
68个来源正式报价场景使用真实GraphRunner的内部类型化入口，其余通过真实聊天图；
20个来源扩展场景使用OpenEvals买家；其中4个长历史场景先执行12轮固定咨询前置，之后动态续谈，保证压力条件真实发生。
可比组现为兼容120集内100个非动态场景＋11原P5场景＝111个，三次重复为333次旧版对照。
其中32个静态聊天场景同样具有不执行正式动作的共同业务预期；不能仅因入口不是结构化报价而排除。
这是120集内部的分组修正，不是重新导入或重复统计100场景祖先版本。

新版适配器将独立旧版调用统一为2048输出、45秒上限、temperature=0、thinking=false、SDK重试0，
逐次保存白名单调用配置并核验；旧代码及业务策略不改。新版还按本输入剩余活动/回复时间缩短超时。

仅截断时再尝试16384一次；两次调用均计账，负面评分不会触发重试。

写入已加入有界共享占用重试。永久失败仍退出，保留追加日志及临时快照。
新版兜底仅统计有质量审核的聊天图，结构化路径的正常确定性渲染另列；旧批次原数值不覆盖。

迁移 `f56ca103e8b2` 增加 `business_causal_events`。每个由图输入提交的买家正式业务动作分别记录
`evidence_resolved → authorization_checked → action_committed → result_published`。
前三项与正式回执同事务提交，第四项与公开消息同事务提交，幂等重放不新增证据。

旧记录不会被自动补造授权轨迹；历史记录缺少证据时评估为证据不足。

## 真实实验

```powershell
..\.venv\Scripts\python.exe -m scripts.run_p5_evaluation --allow-real-model `
  --output ../artifacts/p5/recheck-live --repetitions 3 --concurrency 4 --smoke --legacy --remote
```

输出目录必须不存在。`--select case_id ...` 可用于开发诊断，省略后执行全部非冒烟场景；
`--smoke` 再加入 200 条开发负例。核心场景默认重复三次，冒烟每条一次。
允许 1–8 个不同会话并行，但单个会话始终按真实输入队列串行处理。
不带 `--remote` 时保留本地结果，远端门禁为证据不足。

所需模型和 LangSmith 凭据只从当前项目本地 `.env` 加载，不在命令行打印。
实验没有累计模型费用上限；生产输入仍受 10 次调用、180000 Token、120 秒活动时间等限制。
业务账本覆盖卖家调用，OpenEvals 买家和 judge 单独记录用量及费用；未知费用不能按零处理。

OpenEvals 的 `run_multiturn_simulation` 直接调用真实 GraphRunner；动态场景用
`create_llm_simulated_user` 生成后续买家消息。环境适配器调用真实卖家审批、展示回执及确认接口，
时间到期场景只替换明确登记的到期字段。模型看不到展示凭据或私有策略。

旧版固定提交为 `9fa17569010763860b45d541ce4e2dde46bb7b55`，以 Git archive 提取到本次
输出目录，调用该副本中的原 ChatService、审批处理器和 IntentService；通过原正式报价字段输入。
旧副本使用当前锁定依赖的 Python 运行时以及独立临时 MySQL 库。它不是原部署环境的性能复刻。
原项目代码、`.env` 和数据库不会被修改。

## 数据集、远端回收和门禁

数据集位于 `backend/evaluation/datasets/p5/`，每文件保存内容哈希、场景族、标签来源、允许/禁止
结果与夹具引用。三类风险数据目前是合成候选集，人工标注及代表性字段明确为否。
200 条冒烟包含模板内变化，独立样本数不能按 200 计算。重复运行只用于观测波动。
失败样例的退回登记保存在 `p5_development_regressions.json`，加载时覆盖为开发回归并标记已用于修复；
原始冻结样例和首轮错误记录均保留。相同样例不能因修复后成功而重新获得保留集资格。

每次报告记录代码提交及工作区状态、图版本、数据集/提示词/依赖锁哈希、模型参数及预算。
本地 `results.jsonl` 追加保存每次尝试；`report.json` 保存完整回执、因果证据、账本和汇总。
LangSmith 数据集只保存 case/repeat 引用，实验输出只上传评分、证据哈希和不可授权的运行引用。
业务保持组的两个实验使用同一数据集，便于官方对照。原生图追踪继续使用 P4 严格脱敏客户端。
通过 `runs.query` 分页回读运行结果，再用 `list_feedback` 按确切run ID检查每个评分键和值。
聚合反馈统计存在延迟，不作为完整性依据；缺失、异常或未回收结果均不能通过。

如果仅修正评估器，可对完整已保存对话重新评分，不重复卖家执行，不覆盖原批次：

```powershell
..\.venv\Scripts\python.exe -m evaluation.p5.reassess ../artifacts/p5/recheck-live/report.json `
  --allow-real-model --output ../artifacts/p5/recheck-assessment
```

该命令对全部核心新版和旧版对话重新调用judge，保留前次评分及全部调用费用，重新发布三个实验。
报告同时记录卖家执行提交、评估器提交、公开事实引用哈希和原报告哈希；数据库状态及风险错误不会被重写。
旧版 `REJECTED` 与新版 `OFFER_REJECTED` 仅做同义枚举映射，异常和错误动作仍然失败。
之后将下方门禁命令中的报告路径改为新的 `recheck-assessment/report.json`。

```powershell
..\.venv\Scripts\python.exe -m evaluation.p5.report ../artifacts/p5/recheck-live/report.json `
  --junit ../artifacts/p5/recheck-protocol.xml ../artifacts/p5/recheck-regression.xml `
  --output ../artifacts/p5/recheck-acceptance.json
```

此发布门禁返回码：0=通过，2=失败或证据不足。实验命令本身的成功只表示执行流程完成，
不代表发布许可。没有代表性独立保留集时即使全部开发用例通过，发布门禁仍不通过。
不得删除失败尝试、改标签以提高分数，或把参与修复的失败样例再次用作最终独立保留集。
