# V3 阶段六：结构化可观测性与成本采集

> 状态：已完成。阶段六建立可供阶段七至八直接消费的脱敏事件事实源，不改变任何报价、审批或交易意向授权语义。

## 一、设计结论

本阶段采用“本地 MySQL 事件为主、LangSmith 元数据镜像为辅”的结构：

- `observability_events` 是追加式本地事实源；关闭外部 Trace、网络故障或 LangSmith 写入失败时，核心业务仍按原语义运行；
- 每个 HTTP 请求都有标准 UUID 格式的 `X-Request-ID` 和 `X-Correlation-ID`，同步创建的模型任务继承关联 ID，Worker 恢复时从任务恢复上下文；
- 模型任务和模型调用事件同时记录提供商、模型、输入/输出/缓存/总 Token、运行时单价快照、币种和估算成本，避免未来修改配置后无法复算历史费用；
- LangSmith 只接收相同的脱敏元数据及固定的 `{redacted: true}` 输入输出，不启用 LangChain 自动 Prompt Trace；
- 观测失败采用尽力而为语义，不参与正式业务事务，也不能回滚或放行报价、审批和最终确认。

模式 B 的终点仍是双方对一份有效报价形成交易意向。观测数据不是交易事实，不增加支付、库存锁定、订单或履约能力。

## 二、关联链路与事件契约

所有事件使用稳定的大写枚举名和版本号，关键关联字段为：

| 字段 | 用途 |
|---|---|
| `event_id` / `event_version` | 事件唯一标识和契约版本。 |
| `correlation_id` | 贯通一次 HTTP 发起的聊天任务及后续 Worker 处理；无 HTTP 的恢复任务沿用模型任务原值。 |
| `http_request_id` | 定位单次 API 请求；只接受标准 UUID，非法外部值会被替换。 |
| `session_id` / `model_task_id` | 支持按协商会话或持久化模型任务检索完整链路。 |
| `approval_id` / `offer_id` | 关联审批与报价，不保存用户名或业务正文。 |
| `attempt_count` / `duration_ms` / `error_category` | 描述尝试次数、调用延迟与阶段四的稳定错误分类。 |

当前事件包括：

- `MODEL_TASK_ATTEMPT_STARTED`：一次模型任务尝试开始；
- `MODEL_CALL_COMPLETED`：模型调用成功或失败，成功时携带 Token、价格快照与成本，失败时携带错误分类和是否计划重试；
- `TOOL_ACTION_COMPLETED`：受约束的正式还价、接受或申请审批工具执行结果；
- `CHAT_TURN_COMPLETED`：安全回复落库后的轮次结果及是否产生正式报价引用；
- `APPROVAL_REVIEWED` / `APPROVAL_FOLLOWUP_COMPLETED`：人工审批与通知完成状态；
- `MODEL_TASK_MANUAL_ACTION`：卖家人工重试或终止任务；
- `NEGOTIATION_FINALIZED` / `NEGOTIATION_CLOSED`：买家确认交易意向或关闭会话。

HTTP 完成日志同样输出 JSON，包含路径、状态码、耗时和两个关联 ID；它不复制请求体、Cookie、查询内容或账号信息。

## 三、Token 与成本口径

LangChain 的 `UsageMetadataCallbackHandler` 汇总一次逻辑模型调用中包括结构化输出重试在内的提供商用量。若提供商返回用量，记录：

- `input_tokens`、`output_tokens`、`total_tokens`；
- `cached_input_tokens`，来源为输入 Token 明细的 `cache_read`；
- `.env` 中当前生效的每百万 Token 输入、输出和缓存输入单价；
- `estimated_cost` 和三位币种代码。

计算公式为：

```text
未缓存输入 Token = input_tokens - cached_input_tokens
估算成本 = (
  未缓存输入 Token × 输入单价
  + 缓存输入 Token × 缓存输入单价
  + output_tokens × 输出单价
) / 1,000,000
```

价格没有完整配置、用量没有上报、缓存 Token 超出输入 Token 或存在缓存用量但未配置缓存价格时，系统保留已知 Token 和价格字段，但不编造成本。成本保留八位小数；它是评测和预算用途的估算值，不是提供商账单。

配置示例：

```dotenv
MODEL_INPUT_PRICE_PER_MILLION=2
MODEL_OUTPUT_PRICE_PER_MILLION=8
MODEL_CACHED_INPUT_PRICE_PER_MILLION=0.5
MODEL_COST_CURRENCY=CNY
```

## 四、隐私与安全边界

普通事件属性使用代码内白名单，只允许短枚举、数字、布尔值或空值。以下内容禁止进入本地观测属性、结构化日志和 LangSmith：

- 买家或卖家的用户名、展示名及身份令牌；
- 聊天正文、模型 Prompt、候选回复、审批备注；
- 卖家底价、自动接受阈值和其他私有规则；
- API Key、数据库连接串、Cookie 和异常原文；
- 模型内部推理或思维链。

模型任务的不可变输入仍按阶段二约定保存在受权限控制的业务数据库中，不复制到 `observability_events`。LangSmith 必须通过 `OBSERVABILITY_LANGSMITH_ENABLED=true` 显式开启，并配置独立 API Key；不要设置会自动上传模型输入输出的 `LANGSMITH_TRACING=true`。

## 五、本地查询与导出

导出工具强制要求会话、关联 ID 或模型任务三者之一，避免无边界扫描。JSONL 保留逐事件证据，`summary` 输出事件数、模型成功/失败调用数、Token 覆盖和按币种汇总的估算成本。

```powershell
cd backend
python scripts/export_observability.py --session-id 123 --format jsonl
python scripts/export_observability.py --correlation-id <UUID> --format summary
python scripts/export_observability.py --model-task-id 456 --error-category TIMEOUT
python scripts/export_observability.py --session-id 123 --min-attempt-count 2
```

这些字段将直接作为阶段七模拟运行明细和阶段八报告的底层数据，后续评测不得另建含义冲突的 Token 或成本口径。
