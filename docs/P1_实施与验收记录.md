## 实现范围

1. **真实业务复用**：沿用账号、商品、策略、报价、审批、消息、Agent 消息投影和模型任务表；
   复用纯 `Decimal` 定价授权与报价构造。新增 `*_in_transaction` 操作只用调用方 Session，
   `BusinessCommandService.execute` 统一管理业务、回执、通知义务和 Outbox 的提交/回滚。
2. **组合命令**：提交或替代买家报价，一次事务完成接受、审批请求、经自身授权的还价或拒绝；
   确认、撤回、关闭也走同源结果协议。每次成功新提案加一轮，重复提案不增加轮数，最后一轮
   仍能处理结果与确认。低价拒绝不取消之前有效的报价/审批。卖家批准应用留待 P3。
3. **FIFO 与图恢复**：`negotiation_inputs` 固定请求类型、条款、视图、展示引用、配置与序号，
   每会话最多 20 个未完成输入。任务沿用 `model_execution_tasks`，以 `LANGGRAPH` 隔离旧 Worker。
   GraphRunner 先取 PG 线程锁，再领取队首；使用同连接官方 saver 和 `durability="sync"`。
   新轮、异常续跑、END 收尾、历史重放分别处理；checkpoint 丢失/不匹配保留屏障并显示恢复需求。
4. **展示与确认**：公开结果生成具体报价的上下文，客户端视图登记不可猜测回执；输入接收时
   冻结回执与已展示序号。确认事务复核买家、会话、对象、条款、业务版本、策略、商品和期限。
   P1 内部条款视为可信固定输入；区域运费规则、结构化事实及自然语言语义属于 P2。
5. **独立通知**：正常发布与通知 Worker 共用 `turn:{input_id}:reply`，原子写唯一消息、适用的
   初次确认上下文、通知状态及 Outbox 投递状态。通知持有来源线程锁和独立短租约，只读真实
   回执与当前事实，不调用旧图、不推进输入游标。旧结果发布为历史说明，不开放旧确认卡片。
6. **调用账本**：按 run/步骤/输入/配置保存稳定产物引用，按尝试记录调用、Token 与可估算费用
   预留；未知用量保留预留，成功产物重放前校验哈希，失效所有权的迟到结果不能成为有效产物。
   P1 主图使用确定性文案，预算为零仍能发布已提交结果；完整模型网关与活动时间预算留待后续。
7. **查询与边界**：新增受账号保护的 `GET /api/negotiations/{session_id}/runs/{run_id}`，分别返回
   任务、业务、通知与队列阻塞状态。固定输入和展示登记暂为内部 Python 接口，不新增公开测试
   POST 入口。旧聊天、确认、关闭、审批、任务恢复与 Worker 不能改写已绑定新图的会话。

## 失败记录与修正

| 发现 | 修正及证据 |
|---|---|
| 自动迁移给两条复合唯一约束生成同名索引 | 明确区分 sequence/request 名称；`initial.xml` 保留 19 项 fixture 错误 |
| MySQL 回退不能先删除仍被外键依赖的索引 | 回退按依赖顺序直接删新表，由 MySQL 同时删除其索引；`business.xml` 保留首个失败 |
| 金额内存值与数据库定点值的字符串精度不同 | 条款摘要统一两位小数，避免有效报价摘要误失配；最终同条款重放/确认测试通过 |
| 旧聊天隔离测试未提供测试模型，先触发配置检查 | 补入不会被调用的测试依赖后验证实际业务边界；`graph-api.xml` 保留失败 |
| P1 与 P0 同名测试模块导致联合收集冲突 | P1 更名 `test_graph_recovery.py`；`combined.xml` 保留收集错误，联合复测通过 |

P0 追踪故障用例向本机不可达地址发送合成数据，预期产生 SDK connection-error 日志；这不代表真实
LangSmith 调用或账号问题。上游 LangSmith 弃用提示仍存在，未改变 P0 已记录的后续处理安排。

## 遗留问题与下一步

P1 固定输入切片未发现阻塞退出的问题，以下能力仍不应被当作已交付：

- **P2**：真实语义解析、多意图/草案续接、条件否定、事实与区域成本依据、统一公开聊天、展示 API、
  卡片渲染与上下文刷新。本阶段内部输入的运费是可信测试数据，不能直接暴露给买家作为授权成本。
- **P3**：独立审批图、卖家决定与效力分离、`ApplyApprovalResult`、审批到期和乱序事件对账。
  P1 可创建审批并展示等待结果；旧审批入口明确拒绝处理图会话，等待卖家阶段不会被旧 Runtime 接管。
- **P4**：真实模型网关、所有辅助调用与累计活动时间预算、自然回复审核、上下文记忆、卖家恢复 UI，
  以及真实调用路径的完整脱敏验收。P1 账本与确定性通知测试不等于这些质量验收。
- **P6/运行交付**：新版 runner 实例登记、完整监督器/受限清理部署、服务镜像、容量与 CI、90 天归档。
  P1 CLI 支持轮询/单批运行，SQL 和连接有界；卡死进程的生产自动接管仍需将 P0 已验证协议部署到新版。
