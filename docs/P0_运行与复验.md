# P0 运行与复验

P0 使用 Windows 本地独立 Python 3.11 虚拟环境及 Docker Compose 数据库。
当前 API/前端仍是继承版本；本阶段不启动生产图 Worker。本文命令从新仓库根目录执行，
不在原项目目录执行。模型和 LangSmith 密钥只保存在 Git 忽略的 `.env`。

## 初始化

```powershell
# 新机器使用已有 Python 3.11 建立此目录的独立环境。
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock

# 只按四个允许字段导入模型/LangSmith 配置，其余凭据独立生成。
.\.venv\Scripts\python.exe backend/scripts/bootstrap_p0.py `
  --source-env 'E:\code\agent\个人闲置交易的自主协商卖家助手\.env'
docker compose up -d mysql checkpoint --wait --wait-timeout 120

Set-Location backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m scripts.run_p0_tests
..\.venv\Scripts\python.exe -m scripts.p0_health
```

`run_p0_tests` 首先用独立部署账号执行 saver setup，然后创建受限 checkpoint_worker 和
checkpoint_cleaner 角色。普通图进程无管理员/清理账号环境变量，Worker 不能终止其他会话；
清理角色只能调用核对完整身份的限定函数。setup 不在图请求中执行。

每次测试生成 `p0_test_<随机后缀>` MySQL/PostgreSQL 库，结束后仅删除本次创建的库。
原有回归使用另外两座临时 MySQL 库。测试脚本拒绝原环境地址，不提供 SQLite/内存回退。
连接故障会失败并保留测试结果；不能把 skipped 当作集成验证通过。

资源名为 `secondhand-agent-langgraph`；MySQL 绑定 `127.0.0.1:3307`、checkpoint
绑定 `127.0.0.1:5433`；预留 API 8100、前端 5174。卷为 Compose 自动加此前缀的
`mysql_data`、`checkpoint_data`，没有 external 或旧项目同名显式卷。

## 验证入口

```powershell
# backend 目录；全套 P0 包含本地 HTTP trace 捕获及 SDK 错误注入，无真实模型调用。
..\.venv\Scripts\python.exe -m scripts.run_p0_tests
..\.venv\Scripts\python.exe -m scripts.run_isolated_mysql_tests --ignore=tests/p0
..\.venv\Scripts\python.exe -m pytest
..\.venv\Scripts\python.exe -m ruff check app evaluation tests scripts migrations
..\.venv\Scripts\python.exe -m pip check

# frontend 目录
npm ci
npm run type-check
npm run build
```

数据库测试、真实探测结果在仓库 `artifacts/p0/`（已忽略），脱敏摘要及校验哈希在
`docs/evidence/p0-summary.json`。原始首次失败报告保留，成功复验不删除失败记录。

```powershell
# backend 目录；以下两条会访问外部服务，仅在明确需要复测时执行，输出文件不得覆盖。
..\.venv\Scripts\python.exe -m scripts.probe_p0_model --allow-real-model `
  --output ../artifacts/p0/qwen-new-probe.json
..\.venv\Scripts\python.exe -m scripts.probe_p0_langsmith `
  --output ../artifacts/p0/langsmith-new-probe.json
```

模型探测在调用前落盘预留，最多 6 次、不自动重试；错误仅输出类别，不打印服务异常正文。
同一批不得靠换文件名无限重试；重复批次费用应累计到阶段报告。首次 schema 不支持的 400
允许一次有预算的 JSON 模式回退，但仍经 Pydantic 校验；本次实测使用 json_schema。

LangSmith 仅发送合成数据，使用独立 project；本地默认 `LANGSMITH_TRACING=false`。
当前导出策略保留允许的枚举/计数及运行拓扑，删去自由文本、私有数值、事件正文、附件与
序列化提示词。真实业务接入必须使用该受控 client，不能仅开启环境开关使用默认 client。
P4 若放宽上传内容，须扩展导出边界回归。

## 保留与停止

`docker compose stop mysql checkpoint` 仅停止新项目数据库并保留数据卷。
P0 数据库正常情况下保持运行供下一阶段使用；清理开发数据前另行确认，勿使用原项目名。
故障注入仅操作脚本创建的执行子进程和本次测试数据库内的 PG 会话。
