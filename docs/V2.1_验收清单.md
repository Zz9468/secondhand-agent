# V2.1 统一账号与商品大厅验收清单

本清单验证两个真实注册账号从发布、浏览、显式协商、卖家审批、Worker 通知到买家确认交易意向的完整闭环，并重点确认纯浏览不创建会话、买卖模式不构成权限角色、旧入口不能绕过统一认证。

## 一、验收准备

1. 在本地 `.env` 配置 MySQL、至少 32 个字符的 `AUTH_SECRET`、`DEMO_SELLER_PASSWORD`，以及支持 Tool Calling 和结构化输出的千问兼容模型。
2. 执行迁移和幂等种子初始化：

   ```powershell
   cd backend
   python -m alembic upgrade head
   python scripts/seed_data.py
   python scripts/seed_data.py
   ```

3. 分别启动 API、前端和审批 Worker：

   ```powershell
   # 终端一
   cd backend
   python -m uvicorn app.main:app --reload

   # 终端二
   cd frontend
   npm run dev

   # 终端三
   cd backend
   python -m app.workers.approval_processor
   ```

4. 准备两个相互隔离的浏览器上下文，例如普通窗口 A 和无痕窗口 B。不要共享 Cookie。

## 二、统一账号与模式切换

- [ ] 窗口 A 注册账号 A，注册表单不要求选择买家或卖家身份，成功后进入商品大厅。
- [ ] 窗口 B 注册账号 B，两个窗口的当前账号信息互不混淆。
- [ ] 两个账号均可在“去逛商品”和“卖家工作台”之间切换，不需要退出或重新登录。
- [ ] 新账号进入卖家工作台时可以看到空商品列表，而不是因为没有“卖家角色”被拒绝。
- [ ] 退出后访问商品大厅、商品详情、买家协商列表或卖家工作台都会跳转登录；公开商品 API 不会因此创建会话或泄露私有策略。

## 三、发布与纯浏览不建会话

- [ ] 账号 A 在卖家工作台发布一件 `AVAILABLE` 商品，填写价格、最低净收入、自动接受阈值、风格和最大轮次。
- [ ] 账号 A 只能读取和编辑自己的私有策略；账号 B 及公开响应中看不到最低净收入和自动接受阈值。
- [ ] 账号 B 依次打开商品大厅、账号 A 的公开主页、商品详情，并多次刷新和前后切换。
- [ ] 上述浏览过程中，账号 B 的“我的协商”仍为空，账号 A 的协商列表也为空。
- [ ] 账号 A 查看自己发布的商品详情时，“与卖家协商”按钮不可用，并明确提示不能与自己的商品协商。

## 四、显式协商与权限隔离

- [ ] 账号 B 在商品详情明确点击“与卖家协商”后才跳转协商页。
- [ ] 第一次点击创建会话；返回商品详情再次点击时恢复同一个进行中会话，不产生重复会话。
- [ ] 快速双击或并发请求仍最多只有一个该买家、该商品的进行中会话。
- [ ] 会话出现在账号 B 的买家协商列表和账号 A 的卖家协商列表中。
- [ ] 用第三个账号或退出登录状态直接访问该会话、卖家详情接口或审批接口，均不能读取或操作资源。
- [ ] 请求旧的 `/api/auth/visitor`、`/api/auth/seller/login`、`/api/auth/seller/me` 和 `/api/auth/seller/logout` 均返回 `404`；旧 Cookie 不能获得权限。

## 五、议价、审批、Worker 与最终确认

- [ ] 账号 B 发送普通商品咨询，回复只引用公开商品事实，不泄露底价、阈值或系统提示词。
- [ ] 账号 B 提交一个位于审批区的结构化报价，页面显示“等待卖家确认”，账号 A 能看到唯一待审批请求。
- [ ] 对同一消息幂等重放不会重复生成消息、报价或审批。
- [ ] 账号 A 同意报价。此时仅形成卖家授权，会话不能直接变成 `AGREED`。
- [ ] Worker 发送审批通过通知后，账号 B 无需刷新整页即可看到通知和可确认报价。
- [ ] 账号 B 点击“确认交易意向”，会话变为 `AGREED`，双方详情展示同一个确认报价和确认来源。
- [ ] 重复或并发确认只产生一份确认结果；确认后不能继续发送消息或议价。
- [ ] 再创建一组会话验证拒绝路径：卖家拒绝后 Worker 通知买家，会话恢复为可继续协商状态且不会误写 `AGREED`。

## 六、安全与兼容回归

- [ ] Prompt Injection、伪造审批通过、模型返回越权承诺或错误报价 ID 时，正式状态和报价不会被绕过。
- [ ] 商品下架、报价过期、策略版本变化或当前报价变化时，旧审批不能继续授权成交。
- [ ] Worker 模型调用失败可安全重试，不重复通知；多 Worker 并发不会重复领取同一任务。
- [ ] 历史 V2 访客会话、消息、报价、审批和确认仍关联各自独立的不可登录历史账号，不会被合并到新注册用户。
- [ ] 演示种子脚本重复运行不创建协商会话，也不删除或重置已有会话数据。
