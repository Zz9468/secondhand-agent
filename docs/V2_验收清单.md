# V2 人工验收清单

本清单用于验证“买家议价 → 卖家审批 → Agent 通知 → 买家确认交易意向”的完整 V2 闭环。`AGREED` 只表示双方确认了一份有效报价，不代表付款、库存锁定、订单成立或履约完成。

## 一、验收前准备

1. 确认根目录 `.env` 已配置数据库、`AUTH_SECRET`、`DEMO_SELLER_PASSWORD` 和真实模型参数。
2. 在项目根目录启动 MySQL，并完成迁移和演示数据初始化：

```powershell
docker compose up -d mysql
conda activate secondhand-agent
cd backend
python -m alembic upgrade head
python scripts/seed_data.py --reset-session
```

3. 分别启动后端、前端和审批 Worker：

```powershell
# 终端一：后端
conda activate secondhand-agent
cd backend
python -m uvicorn app.main:app --reload

# 终端二：前端
cd frontend
npm run dev

# 终端三：审批 Worker
conda activate secondhand-agent
cd backend
python -m app.workers.approval_processor
```

4. 准备两个独立浏览器配置文件。窗口 A 用作买家，窗口 B 用作卖家。不要只复制标签页，因为同一浏览器配置会共享 Cookie。
5. 两个窗口都打开 `http://localhost:5173`。窗口 B 切换到“卖家管理”，使用 `demo-seller` 和 `.env` 中的 `DEMO_SELLER_PASSWORD` 登录。

## 二、主闭环验收

1. 窗口 A 勾选“提交正式报价”，填写 `2800` 元、买家承担运费并发送。
2. 买家页面应显示需要卖家确认，会话状态变为“等待卖家审批”，不能把审批说成已经通过。
3. 窗口 B 的“报价审批”数量应自动更新。打开该审批后，可以跳转查看同一会话的消息、报价和审批状态。
4. 卖家填写意见并点击“同意报价”。页面应显示审批已同意、后续状态为等待通知买家；此时会话仍不能显示 `AGREED`。
5. Worker 处理完成后，卖家页面应显示“已通知买家”；窗口 A 无需刷新整页即可看到正式审批通知和“确认交易意向”按钮。
6. 买家点击“确认交易意向”。买家和卖家页面都应显示“意向已达成”，确认报价必须为同一份 `2800` 元报价。
7. 终态页面应明确说明这不是付款或实际成交，并且买家不能继续发送消息或还价。

## 三、关键异常场景

每组场景使用新的浏览器访客身份，或在上一会话结束后刷新页面创建新会话。

| 场景 | 操作 | 通过标准 |
|---|---|---|
| 自动接受 | 正式报价 `2900` 元、买家承担运费 | Agent 可以接受，买家明确确认后才进入 `AGREED` |
| 卖家拒绝 | 正式报价 `2800` 元，卖家选择拒绝 | Worker 通知拒绝结果，会话恢复可协商且不能确认被拒报价 |
| 禁止接受区 | 正式报价 `2600` 元 | 只能拒绝或合法还价，不产生可确认的越权接受 |
| 新报价替换 | 报价进入待审批后，再提交一份新的正式报价 | 旧审批变为取消或失效，只有最新报价可以继续处理 |
| 策略版本变化 | 待审批期间由卖家更新协商策略，再处理旧审批 | 旧审批不能通过并形成有效授权，不能误写 `AGREED` |
| Worker 暂停 | 停止 Worker 后批准报价，再重新启动 Worker | 审批结果先保持待通知；恢复后只发送一条通知 |
| 重复操作 | 连续点击同意、拒绝或确认，或重放同一请求 | 不产生重复审批、消息或交易意向 |
| 关闭会话 | 等待审批时由买家结束协商 | 会话变为 `CLOSED`，待审批被取消且不能继续议价 |
| 身份隔离 | 使用第三个浏览器访客尝试访问窗口 A 的会话 | 返回无权访问或会话不存在，不能读取其他买家数据 |
| 服务重启 | 产生消息和报价后重启后端与前端 | 会话、消息、报价和审批仍存在，页面能恢复真实状态 |

过期审批、并发确认、故障重试和请求幂等还必须由 MySQL 集成测试验证，避免依赖人工计时或快速连点判断。

## 四、自动化验收

在后端目录执行：

```powershell
$env:RUN_MYSQL_INTEGRATION = "1"
python -m pytest
python -m ruff check app tests scripts migrations
python -m alembic current
python -m alembic check
Remove-Item Env:RUN_MYSQL_INTEGRATION
```

在前端目录执行：

```powershell
npm run type-check
npm run build
npm audit --omit=dev --registry=https://registry.npmjs.org
```

验收完成时必须同时满足：主闭环可重复演示；错误身份、旧报价、过期报价、规则变化、拒绝和 Worker 故障不会误写 `AGREED`；买家接口不泄露卖家私有策略；卖家会话接口不返回买家访客标识。
