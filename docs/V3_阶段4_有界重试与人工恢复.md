# V3 阶段四：有界重试、进程重启与人工恢复

> 状态：已完成。聊天决策和审批回访共用错误分类、指数退避、最大尝试次数、过期租约接管和人工处置语义。失败任务可由商品所属卖家定位、额外重试或安全终止。

## 一、目标与边界

本阶段只改造模型任务的执行可靠性，不新增交易业务，不改变价格授权、审批和买家最终确认语义。实现目标为：

1. 临时故障按计划重试，不按 Worker 轮询频率热重试；
2. 尝试次数达到上限或遇到永久错误时停止自动执行；
3. Worker 在模型调用中退出后，新进程可在租约过期后接管；
4. 部分成功不会重复通知，旧 Worker 的迟到结果不会覆盖新状态；
5. 卖家只能处置自己商品产生的任务，人工操作有可追溯记录。

## 二、任务状态与数据迁移

Alembic `20260928_0008` 为 `model_execution_tasks` 增加：

- `max_attempts`：该任务允许的自动尝试上限；
- `manual_retry_count`：卖家授权的额外尝试次数；
- `last_manual_action` / `last_manual_actor_id` / `last_manual_reason` / `last_manual_at`：最近人工处置审计字段。

审批回访状态新增 `MANUAL_REQUIRED`。它表示审批本身已经完成，但买家通知已停止自动重试，需要卖家处置；不得把它解释为报价获得新的授权。

## 三、统一错误分类与退避

`ModelRetryPolicy` 是聊天与审批回访的唯一重试决策入口。稳定分类如下：

| 分类 | 典型来源 | 默认自动重试 |
|---|---|---|
| `MODEL_TIMEOUT` | SDK / HTTP / Python 超时 | 是 |
| `RATE_LIMITED` | HTTP 429 或模型 SDK 限流 | 是 |
| `NETWORK` | 连接错误、HTTP 408/5xx | 是 |
| `INVALID_OUTPUT` | JSON、Pydantic 或结构化输出校验失败 | 是，但受次数上限约束 |
| `BUSINESS_CONFLICT` | 版本、幂等结果或当前业务事实冲突 | 否 |
| `INTERNAL` | 无法安全识别的内部错误 | 否 |

退避使用“基础延迟 × `2^(attempt_count-1)`”，受最大延迟限制，再施加由任务 ID 和尝试次数生成的确定性抖动。确定性抖动既降低多 Worker 同时重试的峰值，也使测试和故障分析可复现。底层异常消息不直接落库，只保存脱敏后的稳定描述。

可配置项：

```text
MODEL_TASK_MAX_ATTEMPTS
MODEL_TASK_RETRY_BASE_SECONDS
MODEL_TASK_RETRY_MAX_SECONDS
MODEL_TASK_RETRY_JITTER_RATIO
MODEL_TASK_LEASE_SECONDS
```

## 四、重启恢复与部分成功对账

`python -m app.workers.model_task_worker` 统一处理到期的聊天决策和审批回访，在两类任务之间轮换领取，避免一类长期占用整批配额。领取规则为：

- `PENDING` 可立即领取；
- `RETRY_WAIT` 只能在 `next_retry_at` 到期后领取；
- `RUNNING` 只能在 `lease_expires_at` 到期后被其他 Worker 接管；
- `attempt_count >= max_attempts` 时直接进入 `FAILED`，不再调用模型。

聊天恢复 Worker 在调用模型前先检查回复幂等键。如果 Agent 消息已经落库、但任务状态因故障未收口，Worker 直接将重复执行置为 `CANCELLED` 并返回已有消息，不发起第二次模型请求。审批回访继续使用 `followup_request_id` 完成同样的去重复核对。

## 五、人工恢复和权限边界

卖家工作台新增“恢复任务”页面，只展示商品、买家显示名、任务状态、尝试次数、脱敏错误分类和人工处置记录。接口不返回模型输入快照、结果快照、业务幂等键或租约令牌。

```text
GET  /api/seller/model-tasks
POST /api/seller/model-tasks/{task_id}/retry
POST /api/seller/model-tasks/{task_id}/terminate
```

- 只有 `FAILED` 可人工重试；每次操作保留历史 `attempt_count`，并且只增加一次额外尝试额度；
- `PENDING`、`RETRY_WAIT`、`FAILED` 和租约已过期的 `RUNNING` 可被终止；活跃租约不能被卖家强制抢占；
- 终止聊天任务时，若还没有 Agent 回复，会使用原回复幂等键写入安全失败回复，避免买家请求永久悬空；
- 终止审批回访后保留 `MANUAL_REQUIRED`，不伪造“已通知”或交易授权。

资源权限由任务关联会话的商品 `seller_id` 决定。非所属卖家的查看和操作都按不存在处理。

## 六、启动与验证

持续 Worker：

```powershell
cd backend
python -m app.workers.model_task_worker
```

单批故障恢复：

```powershell
python -m app.workers.model_task_worker --once --batch-size 20
```

自动化证据覆盖：

- 超时和结构化输出错误的分类、退避和最大次数；
- 任务次数耗尽后不再获取模型租约；
- 审批回访达到上限后进入 `MANUAL_REQUIRED`；
- 模拟 Worker 强制退出、租约过期、新服务实例接管并完成原请求；
- 消息已写入但任务未收口时直接对账，不再调用模型且不重复写消息；
- 多 Worker 并发领取仍只有一个成功；
- 人工查看、额外重试、终止、跨卖家隔离和安全失败回复。

验收必须包含全量 Pytest、MySQL 集成测试、Ruff、Alembic 现有库升级/空库安装/降级再升级、前端类型检查与生产构建。真实模型冒烟沿用显式脚本，不会被普通测试或 Worker 导入隐式触发。
