## 已实现能力

1. **统一公开输入**：新建会话默认绑定 `negotiation-v2`，与创建业务事务一同提交。
   文字聊天、确认按钮、关闭按钮共用 FIFO 与请求去重；消息入口返回 `202`、输入序号、
   `run_id` 和买家消息 ID，OpenAPI 声明异步响应。旧会话保持原版本；P1 的内部固定输入仍不公开。
2. **语义模型与有界规划**：版本化 `IntentFrame`、最多 8 个意图、深度最多 4 的无环依赖。
   校验金额、当前原文引用、配送与费用承担来源、条件、备选分组；对已识别的否定、纠正、
   条件遗漏、冲突及额外承诺增加拒绝执行检查。串行完成独立问题，最多生成一个一致的业务组合。
   模型仅提供候选解释，不能写权威事实、成本或确认凭据。
3. **草案续接**：保留草案 ID/版本、原条件、来源消息、备选组、关联报价和业务版本。
   仅从显式有效引用或发送时冻结的展示上下文续接；多个草案不能由“自提”盲选。
   显式选择和唯一草案补充都会合并并保留原条件；过期或版本冲突不采用执行时最新草案。
4. **商品事实**：增加 `product_fact_values`，支持电池百分数、维修枚举和允许配送方式。
   卖家确认才生成新事实版本并增加商品资料版本；商品描述不能替代结构化事实。
   公开回答标明来源为卖家，未知问题逐项说明，不因无关问题未知而阻断完整报价。
5. **可信成本**：增加区域运费规则和 `CostQuote`，限定商品、区域、方式、承担方、规则版本和期限。
   包邮需要唯一且有效的匹配规则；缺失和重叠均保存草案并创建卖家核实事项。
   自提或买家承担配送费用时卖家配送成本为零，公开表达不会声称买家免运费。
   正式提交重新计算并授权；最终确认重新校验相关事实、成本规则、期限、条款、商品和策略。
6. **核实入口**：卖家页面可维护事实、配送方式、区域成本和失效时间、停用规则、查看待核实草案。
   后台补齐资料只标记草案可继续并唯一通知买家；不会建立或接受旧报价。失败通知可重新核实补发。
7. **展示与回复**：报价和草案卡片随消息返回；客户端实际渲染可见卡片后登记展示回执。
   普通输入冻结当时回执，网络重试保持原载荷；确认使用具体卡片、视图和回执。
   支持为同一仍有效对象刷新上下文；不延长报价、不重发结果消息、不改写旧输入。
   每个意图都有状态与确定性文字；提交结果与投递状态分别展示。
8. **恢复与版本隔离**：P2 使用独立节点定义，保留 P1 图；checkpoint 仅保留运行、产物引用和结果类别。
   语义产物通过 P1 调用账本重放，SDK 不隐式重试。新增真实子进程退出测试验证领取后、
   语义产物后、草案计划后、业务提交后恢复，后续轮次不被旧任务回拨。
9. **私有数据**：卖家成本与优惠不进入公开卡片、P2 买家详情或语义请求。
   语义模型只接收当前输入、是否绑定有效草案/已展示报价、缺失字段；不接收私有定价阈值和回执。

## 发现与修正

- 浏览器验证发现新增卖家组件插入了原 `v-if/v-else-if` 链，中断了商品/恢复任务页面互斥。
  已将组件移到完整链之后，复验商品、事实和核实界面；不是仅以构建成功宣称 UI 通过。
- 补强模型遗漏保护：配送方式和承担方必须有原文依据；两个条件不能只留下一个，电池比较方向
  不能颠倒，已有条件不能在草案续接中被删除。这些程序检查不能替代真实模型语义质量评测。
- 包邮计划完成后规则可能失效，提交时不仅拒绝执行，还保存卖家可操作的核实事项。
- 商品新增资料后，无协商记录的下架商品仍可删除其附属事实/规则；已有协商记录的删除限制不变。
- P0 故障注入向不可达本机端口发送合成追踪，预期 connection-error 与上游 LangSmith 弃用警告仍存在；
  不代表真实远端追踪失败，也未因此更改外部账号。
