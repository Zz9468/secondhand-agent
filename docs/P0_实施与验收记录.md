## 必须用例与技术结论

| 要求 | 已验证内容 |
|---|---|
| A25 | “行”在展示前入库，后生成回执不能改变已冻结输入；账号/对象版本/有效期检查 |
| A27 | 前序 RETRY_WAIT 时第二输入不可领取；前序正确收尾后可领取 |
| A29 | 后续轮次 END 后，历史任务不能重新领取或回拨共享线程 |
| A30 | END 已保存但 MySQL 游标未提交时杀死进程；新进程仅收尾，唯一消息、轮数和动作 |
| A31 | 在报价、审批、轮数/版本、回执、通知、Outbox 六个写入点后逐个异常；全部回滚，重试唯一落库 |
| A32 | 真实独立执行进程卡死且 PG 连接存活；监督器撤销所有权、终止进程、核验连接消失后取得锁/租约 |
| A60 | 领取租约后首次 checkpoint 前退出；无执行产物时原 run 正常首次调用 |
| 持久化 | MySQL 查商品、PostgresSaver、连续轮次字段清零、sync、初始 checkpoint 故障阻断、pending writes、interrupt 跨进程恢复 |
| 产物重放 | 模型产物已入库、动作已提交、公开消息已发布等进程崩溃点分别恢复；无重复产物/副作用 |
| 失效结果 | 旧所有权的模型结果不能成为有效产物或执行命令，只留失效尝试审计 |
| 事务期限 | MySQL 行锁等待和服务端 SQL 执行期限均真实触发；调用方退出整笔事务并释放锁 |
| 单连接/断连 | advisory lock 和 saver 同一 psycopg 连接；其他连接不能抢锁；断开后旧实例不重连 |
| 网络分区 | TCP 黑洞保留数据库侧连接；终止 worker 后由受限清理函数匹配完整身份释放会话，才能接管 |
| 追踪 | 本地实际 HTTP 导出检查及远端读回均无合成私有字段、确认凭据、地址等标记；附件被丢弃 |

接管计时从租约过期算到新实例获得锁/租约，不包含后续模型调用。完整套件中：
30 秒租约卡死场景 **0.235 秒**；分区场景 **0.274 秒**；正常进程退出在租约过期前即可接管。
分区与提前退出采用 2 秒测试租约；权限收紧后分区再次通过。测量前提是本机两个数据库与监督器
可用，不据此声称生产网络也有同等时延。连接断开独立验证了停止、释放和重新取得锁。

## 真实调用与失败记录

三批能力探测共 **9 次 RPC、1699 个已知 token**；含失败及复测的保守预留合计
**0.064810 CNY**，按公开短输入价估算已知费用 **0.0005486 CNY**。账单未核对，预留不当作
实际扣款。没有未知用量 RPC；每批最多 6 次调用且禁止 SDK 自动重试。

最终 4 次异质能力 RPC 的 P50=0.703 秒、nearest-rank P95=0.969 秒，仅作本次探测描述；
不能当作普通协商轮次性能或统计质量门槛。

| 发现 | 处理与保留证据 |
|---|---|
| Python 依赖安装未结束时过早启动检查 | 明确报模块缺失/配置未生成；等待安装后重新初始化并通过，未当成通过结果 |
| 初版租约使用 MySQL FLOAT，Unix 时间精度丢失 | 初轮 21 项中 16 项失败；改为双精度，复测通过；`protocol-initial.xml` 保留 |
| 新 saver 3.2.0 要求 checkpoint >=4.3.0 | 联合解析升级到 4.3.0；原 4.2.0 仅保留在 Git 基线；pip check 与全回归通过 |
| 本地 trace 接收器遗漏 SDK batch config 必填项 | 初轮 native trace 失败；补齐接收器配置，实际批量内容与远端读回均通过；`tracing-model.xml` 保留 |
| 第一批 Qwen 只给格式、未充分定义意图 | 格式通过但意图断言失败，停止该批；保存 `qwen-probe-1.json` |
| 第二批 Qwen 意图正确，但明确 800 元报价的 amount=null | 旧探测只查格式/意图而错误标 passed；原文件不改，summary 明确追加复核失败结论；v3 补充字段定义和精确断言，完整复测通过 |
| PostgreSQL 同账号默认可终止彼此会话 | 撤销 PUBLIC 的直接 terminate/cancel 执行权；Worker 无直接权限，清理账号仅执行完整身份匹配函数；4 项定向复验通过 |

追踪故障测试故意向本地不可达端口导出，会产生预期的 SDK failure 日志；该用例验证调用不阻塞，
不是远端 LangSmith 配置失败。真实远端独立探测已经成功。

## 遗留问题与下一步

P0 关键协议无未验证阻塞项；以下为明确保留的后续工作：

1. P0 是 `p0_*` 表和最小图夹具。P1 要将事务所有权、FIFO、展示回执、通知与恢复协议接到真实
   ORM/API/Worker；不能直接把技术夹具作为生产卖家助手发布。
2. 20 条语义种子和 3 条真实结构化样例不足以证明召回率、误报价/误确认/条件遗漏风险；P2/P5
   需要完整语义契约、开发回归和独立保留集。失败样例保留，不能拿复测成功替代统计证据。
3. 当前 trace 策略会删除自由文本和附件；P4 需要在保持脱敏边界的前提下逐步增加可诊断字段。
   SDK 包导入仍有上游 deprecation warning；远端读取 helper 的 `list_runs/get_run_url` 也已弃用，
   官方提示 2027-01-31 后移除，P4/P5 接入时应迁移并验证新的 runs API。
4. 普通对话 P50/P95、完整调用账本与成本、容量、真实审批竞态、生产监督器部署、CI/Docker 应用镜像
   从零启动尚属后续阶段；P0 没有替代这些验收。
