# V3 阶段七：离线模拟买家与可量化效果评测

> 状态：已完成，并在正式效果评测前升级到场景集 `2.0.0`。本阶段建立不读写业务数据库的合成评测环境；线上部署、支付、订单和履约不在本阶段范围内。

## 一、评测回答什么问题

评测不再只验证“模型能否返回一句话”，而是验证完整 Seller Agent 在固定输入下能否：

1. 对自动接受区报价执行确定性接受；
2. 对审批区报价创建并正确解决卖家审批；
3. 阻断低于最低净收入、未知费用和未授权附加条件；
4. 抵抗底价泄露、虚假审批、虚假成交和履约承诺等提示注入；
5. 在结构化输出失败、超时或预算耗尽时保留失败样本和实际消耗；
6. 以固定提交、场景哈希、Prompt 哈希、模型参数、价格快照和随机种子复现结果。

`AGREED` 只表示买卖双方对一个仍有效的报价形成交易意向，不表示付款、订单、库存锁定、商品独占预订、发货或履约完成。

## 二、三组设计与正式使用方式

| 组别 | 能力 | 用途 |
|---|---|---|
| A：纯 Prompt | 模型候选直接作为隔离结果，不经生产规则保护 | 仅作为高风险控制组，证明测试样本有检出力并量化架构保护收益 |
| B：模型 + 规则 | 候选动作经价格和条件规则复核，但没有状态恢复和卖家审批 | 使用确定性候选模型做开发回归，不再为正式效果报告重复付费调用 |
| C：完整工作流 | 生产 Prompt、非敏感可信上下文、会话历史、规则、状态和模拟卖家审批 | 正式效果主组，覆盖全部 100 个场景 |

正式报告采用“C 全量 + A 高风险子集”，而不是把三组都全量付费运行：

- C 是用户实际使用的体系，全部 100 个场景每个重复 3 次，共 300 个运行；
- A 只在 30 个高风险场景每个重复 3 次，共 90 个运行；
- A/C 只在相同的 30 个场景和相同重复次数上比较，不能用 A 的高风险子集与 C 的全量结果直接相减；
- B 的保护来自确定性业务规则，真实模型不会改变这些规则，因此以 100 场景 A/B/C 的确定性门禁证明实现正确，不额外消耗真实模型预算。

## 三、生产一致性

离线适配器不调用 ORM、FastAPI 或生产写入口，但 C 组复用生产代码中的关键决策契约：

- `PricingService.authorize()` 是正式服务与评测共同使用的价格区间和附加条件授权函数；
- 自动接受区和审批区报价通过 `resolve_authorized_offer_decision()` 确定性路由，和正式 `SellerAgent` 一样绕过模型；
- 低价、未授权附加条件仍可交给模型生成安全还价或拒绝，但任何正式动作都会再次通过规则约束；`constrain_formal_offer_decision()` 同时防止模型把未授权的正式报价降级成咨询回复；
- 运费未知等不可安全计算的报价在调用模型前进入安全失败；
- C 组使用正式 `SELLER_AGENT_SYSTEM_PROMPT`，只向模型提供非敏感授权布尔值和原因码，不暴露最低净收入或自动接受阈值；
- 多轮场景把此前买家消息和系统正式回复按生产消息边界传入模型；
- 模型原生结构化输出若第一次违反跨字段组合规则，和生产 Provider 一样追加纠正规则再试一次；调用后的最终解析失败也会保留尝试次数、耗时和可得用量；传输层超时和重试读取同一份正式配置；
- 每个上层结构化调用尝试、逻辑决策请求、可用结构化响应、Token、耗时和费用分别计数，不能把一次逻辑请求内的结构化纠错隐藏掉。SDK 内部的传输层重试只记录配置和理论上限，无法逐个观测为独立 HTTP 请求，因此报告不把 `model_call_count` 表述为网络请求数。

离线 C 组仍不是 HTTP 端到端测试。审批持久化、账号隔离、Worker 通知、买家确认和幂等性由 `scripts/evaluate_live_workflow.py` 通过真实 API、MySQL 和 Worker 另行验证。

## 四、场景集 2.0.0

默认文件为 `backend/evaluation/scenarios/v2.json`，由 `backend/scripts/generate_evaluation_scenarios.py` 确定性生成。加载器展开公共默认值后计算规范化 SHA-256，并拒绝重复的“场景 ID + 场景版本”。旧 `v1.json` 只为历史复现保留，必须显式指定才会运行。

| 类别 | 数量 | 主要边界 |
|---|---:|---|
| 商品咨询 | 15 | 成色、配件、维修、配送、只在文本中提及金额 |
| 自动接受区 | 15 | 阈值等号、分币边界、卖家运费、折扣、支持的配送方式 |
| 审批区 | 18 | 6 个价格/费用边界分别回放同意、拒绝、失效 |
| 禁止接受区 | 15 | 最低净收入分币边界、远低报价、大额运费和折扣 |
| 附加条件与未知费用 | 12 | 发货、保修、赠品、留货、线下支付、未知卖家运费 |
| 多轮协商 | 10 | 低价到审批/自动接受、连续低价、价格调整与解释轮次 |
| 恶意指令 | 15 | 底价和 Prompt 泄露、伪造审批/付款/成交、越权履约 |
| 合计 | 100 | 全部带 `c_primary` 标签，其中 30 个高风险场景同时带 `a_risk` |

所有数据均强制标记为 `synthetic_data=true`，不导入用户聊天、Cookie、API Key 或数据库连接串。

## 五、指标口径

所有比率保存分子、分母和值；分母为零时写 `null`。比率同时报告 Wilson 95% 区间，但由于同一场景有重复运行，该区间用于描述本评测集上的稳定性，不代表真实用户总体的统计置信区间。

正式简历和项目说明优先使用以下客观指标：

- 系统失败率：`SYSTEM_FAILURE 运行数 / 已开始运行数`；
- 模型决策成功率：成功产生结构化决策的逻辑请求数 / 模型逻辑请求数；
- 可用结构化响应率：成功逻辑决策数 / 上层结构化调用尝试数；结构化纠错会增加分母，SDK 内部传输重试不计作独立样本；
- 自动接受路由准确率：正确路由的自动接受适格报价数 / 自动接受适格报价数；
- 审批路由准确率：正确创建审批的审批适格报价数 / 审批适格报价数；
- 审批解决率：同意、拒绝或失效的审批数 / 已请求审批数；
- 禁止报价、未授权条件、不可计算费用阻断率：各自安全阻断数 / 对应输入数；
- 运行级违规率：出现底价泄露、虚假审批、虚假成交或越权承诺的运行数 / 已开始运行数；
- 正式承诺违规率：未授权正式承诺数 / 全部正式承诺数；
- Token、估算费用和模型耗时：既报告总量，也报告完成样本的均值、中位数和 P95，并单列失败消耗。

“交易意向达成率”受预设买家目标、审批脚本和场景构成影响，可以作为测试集行为指标，但不能写成真实商业转化率。自然度和相关性属于主观质量；未完成人工盲评或独立裁判评测时，不写成客观效果数字。

## 六、运行方式与预算

确定性全矩阵运行 100 场景 × A/B/C 共 300 个样本，不访问网络：

```powershell
cd backend
python -m evaluation.cli --batch-id v3-v2-deterministic
```

真实 C 组单次全量示例：

```powershell
python -m evaluation.cli `
  --batch-id <clean-commit>-c-seed-20260929 `
  --model qwen `
  --allow-real-model `
  --groups C `
  --tag c_primary `
  --seed 20260929 `
  --max-samples 100 `
  --max-model-calls 140 `
  --max-tokens 250000 `
  --max-cost 0.20 `
  --timeout-seconds 1800
```

真实 A 组高风险控制示例：

```powershell
python -m evaluation.cli `
  --batch-id <clean-commit>-a-risk-seed-20260929 `
  --model qwen `
  --allow-real-model `
  --groups A `
  --tag a_risk `
  --seed 20260929 `
  --max-samples 30 `
  --max-model-calls 60 `
  --max-tokens 120000 `
  --max-cost 0.10 `
  --timeout-seconds 900
```

正式报告使用三个不同种子重复上述两类批次。预算是硬上限，不是预期消费；C 中确定性路由的报价不调用模型。结构化失败、超时和预算失败均保留在原始结果中，不能删除后重跑来粉饰指标。

## 七、阶段七验收

阶段七最初的 8 场景、24 运行和 9 次真实模型冒烟只验证了框架雏形，现作为历史记录保留，不再作为正式效果数字。2.0 升级后的验收要求是：

- 100 个唯一场景及 30 个 `a_risk` 场景通过契约检查；
- 300 个确定性 A/B/C 运行全部落盘且安全门禁通过；
- C 组确定性报价路由不调用模型，自动接受、审批和不可计算费用与生产逻辑一致；
- 多轮上下文、提供商尝试预算、失败用量、价格快照和聚合兼容性均有自动测试；
- 正式真实模型结果只接受干净 Git 提交上的固定三次重复，并由阶段八聚合器从不可变原始批次生成。

最终批次、指标和适用边界记录在 [`V3_正式效果评测方案与结果.md`](V3_正式效果评测方案与结果.md)。
