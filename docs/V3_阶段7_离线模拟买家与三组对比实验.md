# V3 阶段七：离线模拟买家与三组对比实验

> 状态：已完成。阶段七建立独立、无数据库写入的 A/B/C 离线实验框架；阶段八将在这些原始结果之上增加正式报告、回归门禁和容器化复现交付。

## 一、设计结论与边界

阶段七新增 `backend/evaluation/`，但不接入 FastAPI 路由、业务 Service 写入口、ORM Session 或 Alembic。三组都运行在单样本内存状态中，清单固定记录 `database_type=none-in-memory` 和 `migration_version=not-applicable`，因此不会创建、修改或清理开发/生产业务数据。

三组共用同一份版本化场景、商品事实、买家目标、逐轮输入、最大轮次、超时、随机种子和买家输入哈希，只改变被评估的系统能力：

| 组别 | 能力 | 隔离执行语义 |
|---|---|---|
| A：纯 Prompt | 模型候选直接作为对照结果 | 不复用生产写入口；隔离适配器直接判断候选承诺和敏感声明是否违规。 |
| B：模型 + 规则 | 模型给候选，确定性价格与附加条件规则复核 | 没有人工审批能力；审批区报价不能被当作已授权事实。 |
| C：模型 + 规则 + 状态/人工审批 | 在 B 的基础上保存样本内状态并回放预定义卖家审批 | 只有规则复核及审批授权均通过后才能形成有效正式承诺。 |

A 组只是用于说明架构约束的价值，永远不进入正式业务路径。C 组复用了生产价格规则的语义，但使用独立的内存适配器，不把模拟事实伪装成线上数据库记录。模式 B 的业务终点仍只是交易意向，不增加支付、库存锁定、订单或履约能力。

## 二、版本化场景与公平性

`evaluation/scenarios/v1.json` 的场景集版本为 `1.0.0`，包含八类合成数据：

1. 普通商品咨询；
2. 自动接受区的正常报价；
3. 远低于底价的试探；
4. 多轮议价；
5. 包邮与当日发货等未知附加条件；
6. 需要卖家审批的报价；
7. 要求泄露底价、伪造审批和履约承诺的恶意指令；
8. 模拟模型超时。

加载器拒绝重复的“场景 ID + 场景版本”，并对规范化场景内容计算 SHA-256。每个场景必须显式标记 `synthetic_data=true`。模拟买家按脚本回放，并为完整输入计算稳定哈希；测试会校验同一场景在 A/B/C 三组中的输入哈希完全相同。

默认确定性候选模型用于普通回归，不访问网络。真实千问模式使用相同场景和结构化 `NegotiationDecision`，只有显式传入 `--model qwen --allow-real-model` 才能开启。真实评测强制关闭 SDK 隐式重试，使一条模型调用事件对应一次提供商请求；调用数、Token、费用和总时长仍受批次预算约束。

## 三、运行、错误隔离与预算

`EvaluationRunner` 在启动任何样本前校验样本预算，然后按场景和实验组运行。每个运行均先产生 `RUN_STARTED`，模型错误、场景超时、批次超时、调用/Token/费用预算耗尽以及未预期的执行器异常都会归类为 `SYSTEM_FAILURE` 并进入结果集。一个运行失败不会抛弃已经完成的运行，也不会阻止后续样本获得自己的失败或成功记录。

预算字段包括：

- 最大样本数；
- 最大模型调用数；
- 最大 Token；
- 可选的最大估算费用；
- 批次总超时和每场景超时。

使用费用上限时必须同时配置输入、输出单价和币种。模型实际用量会先写入运行事件，再执行调用后的 Token/费用上限检查，避免把已经发生的消耗漏记为零。
即使结构化输出校验失败，只要提供商回调已经返回用量，失败事件和运行汇总也会保留对应 Token 与估算费用；错误类别不会覆盖已经发生的消耗。

默认确定性批次：

```powershell
cd backend
python -m evaluation.cli --batch-id stage7-local
```

受控真实模型小样本示例（会访问付费服务）：

```powershell
cd backend
python -m evaluation.cli `
  --model qwen `
  --allow-real-model `
  --scenario-id near_listed_price_offer `
  --scenario-id seller_approval_zone_offer `
  --scenario-id prompt_injection_floor_leak `
  --max-samples 9 `
  --max-model-calls 9 `
  --max-tokens 30000 `
  --max-cost 1.00 `
  --timeout-seconds 300
```

结果默认写入被 Git 忽略的 `backend/evaluation/results/<batch_id>/`。同名批次目录已存在时拒绝覆盖，避免误删或混合历史证据。

## 四、原始产物与指标复算

每个批次保存四个文件：

| 文件 | 内容 |
|---|---|
| `manifest.json` | Git 提交与脏状态、应用/Python 版本、场景版本和内容哈希、模型与 Prompt 配置、随机种子、预算、开始/结束时间和失败数。 |
| `events.jsonl` | 按运行展开的逐轮追加式事件，包括买家输入、模型结果、规则/审批结果、用量和终态。 |
| `runs.jsonl` | 每个样本的终态、违规、轮次、正式承诺、审批及模型用量汇总。 |
| `summary.json` | 按 A/B/C 分组、依照阶段一冻结公式计算的指标。 |

汇总同时保留每个比率的分子、分母和值；分母为零时值为 `null`。当前实现包括交易意向达成率、有效结束率、运行级违规率、正式承诺违规率、平均协商轮次、审批率、用量覆盖率、模型调用、Token、按币种费用以及系统失败额外消耗。正式的 Markdown/CSV 报告、分位数和自动门禁属于阶段八，届时只能从这些机器可读原始记录生成，不能手工改数字。

清单和结果不保存 API Key、数据库连接串或 Cookie。逐轮消息来自强制标记的合成场景；如未来允许导入其他场景，必须先升级数据契约和隐私审查，不能直接复用本入口。

## 五、验收证据

阶段七新增的确定性测试验证：

- 场景版本、类别覆盖、唯一性和合成数据约束；
- 三组输入指纹一致，24 个默认样本全部进入结果集；
- 三个模拟模型超时分别进入 A/B/C 的 `SYSTEM_FAILURE`，整批继续完成；
- A 组能暴露未授权承诺，B/C 规则组阻止同类违规，C 组能完成审批区授权；
- 指标保留冻结口径的分子和分母，零分母返回 `null`；
- 样本预算在模型调用前拒绝超限批次；
- JSON/JSONL 可解析、不包含密钥字段、拒绝路径逃逸和覆盖同名批次。

本阶段的 24 样本确定性冒烟结果只证明运行器和规则差异可复现，不作为真实模型能力结论或简历数字。真实模型对比结果及报告将在显式预算下单独运行，并由阶段八产物记录对应提交和配置。

## 六、本轮验收记录（2026-09-28）

- 默认确定性批次完成 24 个样本并写出 24 条运行明细、128 条逐轮事件；三个预置模型超时分别进入 A/B/C 的 `SYSTEM_FAILURE`，没有中断后续运行；
- 第一次真实模型小样本共 9 次调用，全部因评测 Prompt 未明确 `NegotiationDecision` 的跨字段组合条件而进入 `STRUCTUREDOUTPUTVALIDATIONERROR`；该批次原样保留，没有删掉失败记录；
- 随后将生产决策契约使用的 `DECISION_FIELD_RULES` 纳入三组 Prompt 并升级 Prompt 版本至 `v3-stage7-1.0.1`。第二次真实模型小样本启动 9 个运行，8 个得到可判定业务终态，1 个仍以结构化输出校验失败进入 `SYSTEM_FAILURE`，证明单样本失败隔离有效，也再次说明真实模型结果不能靠重跑粉饰；
- 真实冒烟只选择正常报价、审批区报价和恶意指令三个场景。调用上限 9、Token 上限 30,000、估算费用上限 0.10 CNY、批次超时 300 秒；实际有用量覆盖的 8 次调用共 4,680 Token，按本次价格快照估算 0.00215460 CNY；
- 本次临时价格快照依据[阿里云百炼公开价格](https://help.aliyun.com/zh/model-studio/model-pricing)中北京区 `qwen3.7-flash` 的 32K 以内实时输入 0.2 CNY/百万 Token、输出 0.8 CNY/百万 Token；缓存输入为避免低估，临时按普通输入价格计算。只向评测进程注入这些值，没有修改或提交 `.env`；
- 带健康 MySQL 的后端全量套件为 209 passed、1 skipped；跳过项是需要独立临时数据库地址的破坏性迁移专项，本阶段没有数据库模型或迁移变更；
- Alembic 当前版本与唯一 head 均为 `20260928_0009`，`alembic check` 无待生成操作；Ruff、前端严格 TypeScript、Vite 生产构建、Python 依赖审计和前端生产依赖审计全部通过；
- 确定性与真实冒烟产物均位于被 Git 忽略的本地 `backend/evaluation/results/`，不会随源码提交，也没有写入业务数据库。

这两次真实模型运行只用于验收适配器、预算和错误记录，不是阶段八的正式对比报告。正式报告必须在干净提交上重新运行完整场景集，并将失败样本、模型版本和价格快照一并公开。
