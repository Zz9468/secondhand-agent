## 普通对话升级与思考模式（2026-10-06，上一阶段）

用户反馈“继续增加决策类型无法覆盖新场景”，本次把普通咨询升级为 `conversation-v1`。`finish_turn` 的普通计划是 `action / reason / reply / needs_clarification / topics`，action 仅保留非写操作 INQUIRY/REJECT，topics 可空、可任意文本。普通回复由模型依据公开事实组织，主题不用于路由或替换回复；保留 GENERAL 仅用于适配既有业务决策载体。正式还价、接受、审批仍使用有限的业务工具和后端授权，正式承诺文案继续从执行结果生成。

每个普通候选先检查明显越权承诺与内部机制泄露，再通过独立 `REPLY_REVIEW` 调用检查是否回答本轮问题及肯定事实的来源。审核提供具体 claim、字段路径和原文片段，后端核对叶字段、原文和绑定的回复/事实哈希。审核成功才能发布原候选；失败回执进入执行流，最新修正理由固定在下一次上下文中，原文重复不能重新抽样审核。相关审核调用、用量和实际参数进入既有 `agent_call_snapshots`；裁决留在任务 checkpoint，恢复可复用已有快照或裁决，不增加数据库表。

主模型已启用 `MODEL_ENABLE_THINKING=true`，`MODEL_THINKING_BUDGET=768`、`AGENT_OUTPUT_TOKEN_RESERVE=3072`。审核和 JSON 收尾调用使用思考预算 1024、输出预留 3072；每次实际调用继续检查上下文、输出空间、Token、费用及时间。思考参数按任务冻结，既有任务不改写；非思考的历史契约回归显式关闭思考以免受本地配置漂移影响。参数依据见[阿里云思考预算文档](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)。思考会增加调用耗时，不能替代业务授权或事实核对。

本轮新增开放主题、审核修复、虚假证据、截断、正式报价约束、幂等与恢复测试。最新全量隔离 MySQL 回归 **347 passed，0 skipped**，Ruff 检查通过；前端 vue-tsc 和 Vite 构建通过，Nginx 检查通过。隔离测试库已清理，实际用户会话保留。

## 数据与执行契约

- `agent_messages` 保存原始输入、模型候选、工具调用及结果、公开回复、通知和上下文修订。原始消息不因摘要被改写或删除。现有 `messages` 保留公开对话，由同一事务建立唯一投影关联。
- `agent_session_contexts` 保存最新摘要和记忆，分别维护版本、覆盖位置和来源。历史修订仍记录在原始流中。缓存用于下一轮增量构建，实际模型输入以调用快照为准。
- `agent_call_snapshots` 保存实际消息、提供商可见消息、工具 Schema、工具选择、输出约束、参数、响应、用量和失败状态。未知用量保留未知。
- 系统提示词采用版本化资源，任务创建时冻结文本与 SHA256，每次实际请求记录其输入。模型恢复沿用冻结配置，不把历史系统提示当成当前指令。
- Native Runtime 在每次模型调用、工具执行和状态保存前核验预算、租约和业务版本。正式写动作、工具回执、公开消息和任务完成原子提交；RPC 不占用长数据库事务。
- 一个工具批次最多一个终结工具，且必须最后执行。模型不能凭聊天数字接受正式报价；包邮费用未知时只能澄清，不能猜测后写入。
- 新任务使用 `structured-finish-v2` 结束策略：探索若返回自由文本，先仅绑定并指定 `finish_turn`；仍返回纯文本时改用不绑定工具的 JSON Schema 结束请求，最后一个模型步骤也保留给结构化收尾。原始 JSON 和内部执行封装分别标识；该请求计入步骤、Token、费用及恢复快照，只允许咨询或拒绝。旧任务沿用冻结策略。
- 新任务使用 `contiguous-prefix-v1` 记忆补偿策略：超长历史按连续前段提取，只有成功处理的前段推进覆盖位置。历史补偿失败时，即使本轮记忆更新成功，也不跳过遗漏的历史。单条过大的历史保留原文与未覆盖状态，不假报已处理。

千问官方文档说明 `required` 在非思考模式下不能保证工具调用，指定函数可用于限制结束步骤。因此实现没有依赖 `required` 获得执行保证：[Function Calling 文档](https://help.aliyun.com/en/model-studio/qwen-function-calling)。即使指定函数，后端仍校验返回工具名、参数和权限。
