# V3 正式效果评测方案与结果

> 当前状态：正式评测已完成。以下结果来自 Git 提交 `c82956c9641abc133592146fed5d4c19e5913b21` 的干净工作区，保留全部失败样本，并由六个不可变真实模型批次聚合生成。

## 一、目标

本报告为简历、项目介绍和现场演示提供可复核的真实模型效果指标。它测量 SecondHand Agent 在版本化合成场景上的系统行为，不测量真实平台成交率，也不把交易意向描述为支付或订单完成。

主结论来自 C 组完整工作流；A 组只用于 30 个高风险场景的同输入控制对比；B 组由确定性全矩阵门禁验证，不重复进行付费模型实验。

## 三、开发态验收记录

以下结果用于验证评测器和正式业务链路，不是最终简历数字：

- 场景集 2.0.0 的 300 个确定性 A/B/C 运行全部完成，安全门禁 `PASS`；
- C 组确定性评测中，自动接受、审批、禁止报价、未知附加条件和不可计算费用均按生产规则路由或阻断；
- 真实 FastAPI + MySQL + Worker 工作流 8/8 通过，覆盖审批同意/拒绝、通知、买家确认、幂等和跨账号隔离；
- 第一轮 12 场景 A/C dirty 试跑暴露了结构化失败和 C 组生产路由不一致；对应原始批次保留，但不进入最终聚合；
- 修复后对全部 30 个高风险场景执行 A/C dirty 试跑，共 60/60 完成且零系统失败。C 为 0 规则违规、低价阻断 5/5、未授权条件阻断 10/10；A 产生 14/14 个未授权正式承诺。A/C 分别发生 36/34 次上层结构化调用，逻辑决策均为 30/30 成功；总计 69,539 Token，按冻结价格估算 0.02129960 CNY；
- 逐条复核该试跑时发现旧文本检测器把“您提到承诺包邮”误判为系统承诺，随后改为肯定式声明检测并增加拒绝/引用回归样例。因此 dirty 批次中的运行违规计数不作为最终结果，最终批次会使用修复后的检测器；
- C 组私有价格上下文泄露、多轮历史缺失、未授权正式报价的动作约束、结构化重试/最终解析计数、A/C 随机种子配对、聚合报告完整性和正式价格快照记录均已修复；
- 真实工作流验收曾捕获“审批通知 Worker 与卖家详情轮询”的 MySQL 1213 死锁。详情查询现在不再获取业务行写锁，仅已到期待审批进入独立短写事务；修复后连续 4 轮真实 FastAPI + MySQL + Worker 验收共 32/32 通过，API/Worker 无异常、死锁或 HTTP 500；
- 改动冻结前共收集 237 个测试，含 MySQL 与破坏性迁移的全量结果为 236 passed、1 skipped；Ruff、Alembic `current/heads/check`、前端生产构建、Python/npm 生产依赖审计、Compose 配置均通过且漏洞数为 0；
- Windows PowerShell 5.1 曾因无 BOM 的中文脚本解析失败，修复为 UTF-8 BOM 后使用同一 `powershell.exe` 入口完成真实 HTTP 交易意向闭环和 300 个 A/B/C 确定性样本，零系统失败且门禁 `PASS`。

### 4.4 失败与成本完整记录

六批合计 390 次运行、322 次提供商尝试、367,813 Token，估算费用 `0.07669564 CNY`，用量覆盖 322/322。四个系统失败均原样保留：

四个失败共消耗 8 次提供商尝试、10,015 Token 和 `0.00326112 CNY`，均已计入总量。A / seed `20260930` 和 C / seed `20261001` 为零系统失败。没有为改善数字而删除、覆盖或重跑任何已开始的正式批次；一次在样本启动前因遗漏当前 shell 的币种环境变量而被预检拒绝，未创建批次目录，也不属于运行样本。

## 五、结论、简历表述与边界

### 5.1 可以写入简历的保守表述

> 构建具备确定性报价授权、人工审批和失败可观测性的二手交易 Seller Agent；在 `qwen3.7-flash`、100 个版本化合成场景 × 3 次重复的正式离线评测中，实现规则违规 0/300、未授权正式承诺 0/90、适格报价路由 126/126，模型决策成功 193/195（99.0%）；在 30 个高风险场景 × 3 的同输入 Prompt-only 对照中，将规则违规从 44/90（48.9%）降至 0/90，并通过 8/8 个真实 HTTP + MySQL + Worker 闭环用例。

简历或面试中应同时说明“版本化合成场景”“正式离线评测”和样本量，不能只写孤立的百分比。

### 5.2 不能据此声称

- 不能把 26.0% 意向达成率写成真实用户成交率、支付成功率或 GMV 提升；
- 不能声称线上零故障、99.99% 可用性或所有输入下安全，因为正式 C 组仍有 2/300 系统失败；
- 不能把适格路由和阻断的 100% 扩展为“模型准确率 100%”，这些是冻结规则和已覆盖场景上的确定性结果；
- 不能声称自然度、说服力、满意度或不必要让步已有量化结论；本轮没有填写 `manual_review.csv` 的主观质量评分；
- 不能把 A 描述为外部竞品或旧线上系统，它只是同模型、同输入的 Prompt-only 消融对照。

### 5.3 结果限制

- 场景为版本化、人工设计的合成集合，覆盖已知边界与攻击面，但不代表真实平台流量分布；
- 三次重复按运行级计算 Wilson 区间，没有对同一场景的聚类相关性建模；temperature 为 0 仍可能受提供商服务和模型别名更新影响；
- 离线主实验不访问业务数据库；数据库、并发、鉴权和 Worker 由 8 个真实 HTTP 闭环及 MySQL 集成测试补充验证；
- 费用按 2026-09-29 冻结公开单价估算，不含账户折扣，也不等于最终账单；
- 主观回复质量仍需独立盲评或真实用户实验。若未来加入 LLM-as-judge，应先冻结 rubric、评审模型和人工抽检方案，不能把当前安全事实指标与主观评分混为一谈。
