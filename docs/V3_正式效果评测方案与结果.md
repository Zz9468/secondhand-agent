# V3 正式效果评测方案与结果

> 当前状态：评测实现和开发态验收已完成；正式结果必须在本次改动提交后的干净工作区运行，本文件将在不可变批次聚合完成后补入最终数字。

## 一、目标

本报告为简历、项目介绍和现场演示提供可复核的真实模型效果指标。它测量 SecondHand Agent 在版本化合成场景上的系统行为，不测量真实平台成交率，也不把交易意向描述为支付或订单完成。

主结论来自 C 组完整工作流；A 组只用于 30 个高风险场景的同输入控制对比；B 组由确定性全矩阵门禁验证，不重复进行付费模型实验。

## 三、开发态验收记录

以下结果用于验证评测器和正式业务链路，不是最终简历数字：

- 场景集 2.0.0 的 300 个确定性 A/B/C 运行全部完成，安全门禁 `PASS`；
- C 组确定性评测中，自动接受、审批、禁止报价、未知附加条件和不可计算费用均按生产规则路由或阻断；
- 真实 FastAPI + MySQL + Worker 工作流 8/8 通过，覆盖审批同意/拒绝、通知、买家确认、幂等和跨账号隔离；
- 第一轮 12 场景 A/C dirty 试跑暴露了结构化失败和 C 组生产路由不一致；对应原始批次保留，但不进入最终聚合；
- 修复后对全部 30 个高风险场景执行 A/C dirty 试跑，共 60/60 完成且零系统失败。C 为 0 规则违规、低价阻断 5/5、未授权条件阻断 10/10；A 产生 14/14 个未授权正式承诺。A/C 分别发生 36/34 次上层结构化调用，逻辑决策均为 30/30 成功；总计 69,539 Token，按冻结价格估算 0.02129960 CNY；
- 逐条复核该试跑时发现旧文本检测器把“您提到承诺包邮”误判为系统承诺，随后改为肯定式声明检测并增加拒绝/引用回归样例。因此 dirty 批次中的运行违规计数不作为最终结果，最终批次会使用修复后的检测器；
- C 组私有价格上下文泄露、多轮历史缺失、未授权正式报价的动作约束、结构化重试/最终解析计数、A/C 随机种子配对、聚合报告完整性和正式价格快照记录均已修复；
- 真实工作流验收曾捕获“审批通知 Worker 与卖家详情轮询”的 MySQL 1213 死锁。详情查询现在不再获取业务行写锁，仅已到期待审批进入独立短写事务；修复后连续 4 轮真实 FastAPI + MySQL + Worker 验收共 32/32 通过，API/Worker 无异常、死锁或 HTTP 500；
- 改动冻结前共收集 237 个测试，含 MySQL 与破坏性迁移的全量结果为 236 passed、1 skipped；Ruff、Alembic `current/heads/check`、前端生产构建、Python/npm 生产依赖审计、Compose 配置均通过且漏洞数为 0；
- Windows PowerShell 5.1 曾因无 BOM 的中文脚本解析失败，修复为 UTF-8 BOM 后使用同一 `powershell.exe` 入口完成真实 HTTP 交易意向闭环和 300 个 A/B/C 确定性样本，零系统失败且门禁 `PASS`。
