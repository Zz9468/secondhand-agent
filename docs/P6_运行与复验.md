# P6 清理与可交付运行：运行与复验

## 环境和启动

生产入口为 `app.main:app`、`app.workers.graph_worker` 与 `app.workers.graph_watchdog`。最短初始化命令见 [README](../README.md)。`docker compose up -d --build frontend` 会启动完整依赖。

初始化任务分别执行 MySQL `alembic upgrade head` 和 PostgreSQL 官方 `PostgresSaver.setup()`。`checkpoint-setup` 创建普通 `checkpoint_worker` 与独立 `graph_cleaner`，撤销 PUBLIC 直接 terminate/cancel 权限；清理函数只匹配本库、普通 Worker 账号、完整 application_name、PID 和 backend_start。不要在事务池代理后运行持有 session advisory lock 的连接。

`bootstrap_p6` 保留现有配置，只补充缺失或 CHANGE_ME 值。既有数据库口令不会被自动轮换；首次生成的演示密码保存在本地 `.env`。运行应用的环境不包含数据库管理员或清理口令，watchdog 不接收模型与认证密钥。

源码方式在 `backend/` 的三个终端中分别运行（先用 Compose 完成双库初始化和迁移）：

```powershell
$env:GRAPH_REQUIRE_SERVICES = 'true'
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8100
# 另开终端
..\.venv\Scripts\python.exe -m app.workers.graph_worker --batch-size 20
# 再开终端；清理连接从本地 .env 读取
..\.venv\Scripts\python.exe -m app.workers.graph_watchdog
```

前端 `frontend/` 执行 `npm run dev -- --host 127.0.0.1 --port 5174`，设置 `VITE_API_PROXY_TARGET=http://127.0.0.1:8100`。不要与完整 Compose 应用同时占用端口。

## 监督、恢复和告警

每个图执行使用独立 UUID，先登记 PostgreSQL 精确连接身份，再取得线程锁并绑定 MySQL token/代次。执行子进程每 5 秒续租，租约最长 30 秒。父监督器检查租约、活动/回复期限和 150 秒绝对上限；只对自己登记的 token/代次撤销所有权，然后终止自己创建的进程。子进程退出不等于 PostgreSQL 连接已释放。

独立 watchdog 每秒扫描登记表。过期实例先在有界 MySQL 事务中撤销 token/递增代次并保存 `REVOKED`，提交后再调用受限清理函数；核验连接消失后保存 `RELEASED`。清理失败保留错误类别，可重复执行；不跨越存活线程锁接管。父进程重启后，watchdog 仍能根据持久化登记清理孤儿连接。新实例最终必须取得原 PostgreSQL 线程锁。

`/api/health` 仅表示 API 进程存活。Compose 的 `/api/ready` 检查 MySQL、checkpoint 表、Worker/watchdog 最近 20 秒的进展和配置；失败返回 503。它不触发收费模型请求。容器健康与结构化 stdout 是本地告警信号：

```powershell
docker compose ps
docker compose logs --tail 100 api worker watchdog
```

业务失败由卖家“恢复任务”页处理：同队首、同 run_id 的一次重试；不重置预算的安全终止；已提交结果的通知重试。恢复操作需原因和稳定 request_id，并保留审计。严禁手改 checkpoint 或删回执“修复”。外部告警收件人和监控账号未配置，本阶段未向任何外部人员发送消息。

| 信号 | 处理 |
|---|---|
| Worker 不健康 | 检查 MySQL、子进程与日志；恢复同版本 Worker |
| watchdog 不健康 / `checkpoint_cleanup_failed` | 检查受限角色和双库连接；保留 REVOKED 记录后重试 |
| 已提交但未通知 | 检查独立通知和卖家通知恢复，不重做报价 |
| 无有效模型配置 | 配置密钥并重建 API/Worker；就绪探测不证明模型能力 |
| P5 远端 429 | 保留真实本地 callback，按 P5 重传手册恢复；不编造远端 span |

## 容量边界

默认 1 个 Worker，每个父进程串行监督一个执行子进程；batch-size 是扫描数量，不是并发数。API MySQL 连接池 5+5，图父/子进程各 3+1，独立 watchdog 3+1，连接等待 3 秒、MySQL 连接 3 秒/读写 5 秒；PostgreSQL 专用连接单次语句 5 秒、锁等待 2 秒。容量配置必须给 API、通知、健康和清理留余量。

本地交付验证不等于吞吐 SLA。扩容可从 `docker compose up -d --scale worker=2 frontend` 开始，同一会话仍由锁与队首规则串行；增加副本前按每个父/子进程最多 8 个 MySQL 连接、最多若干独立通知/审批 PG 连接估算余量，再做真实负载验证。不得用增加数据库上限替代容量测试。

## 版本和回退

迁移 head `a67db214f9c3` 增加执行登记及服务心跳，不转换既有协商语义。空库执行升/降/升已包含在协议回归；有实例审计时 P6 降级会拒绝删除恢复依据，P4/P5 同样保护历史产物。

新会话使用 negotiation-v3，既有图按原契约继续。设置 `GRAPH_CHAT_ENABLED=false` 仅停止新建协商，已有图输入继续处理；需要完全停写时停止 API。回退应保留双库、恢复兼容图 Worker；生产路由不再接受旧式结构化聊天或旧模型任务恢复接口。旧项目仍是独立环境，不能把新版报价交给旧 Runtime。

## 备份、归档和恢复

终态至少保留 90 天。未完成输入、待审批/应用、待通知、有效展示、待执行 checkpoint 和恢复义务阻止归档。归档先写 MySQL 会话墓碑，再删该会话整组主图/审批 checkpoint；中断可重跑，墓碑阻止历史重试重新执行。业务审计、请求/动作幂等键、模型产物和清理审计继续保留，不自动物理删除。

对双库备份前停止所有应用写入，包括源码方式的进程。备份工具拒绝运行中的 Compose API/Worker/watchdog，输出 MySQL SQL、PostgreSQL custom dump、SHA-256 和来源实例/时间。

```powershell
# 项目根目录
docker compose stop frontend api worker watchdog
cd backend
..\.venv\Scripts\python.exe -m scripts.backup_p6 --output ../artifacts/backups/pre-archive
# 默认 dry-run
..\.venv\Scripts\python.exe -m scripts.archive_graph_session 123
# apply 必须验证同一 MySQL 实例、最近24小时、双文件哈希
..\.venv\Scripts\python.exe -m scripts.archive_graph_session 123 --apply --backup-manifest ../artifacts/backups/pre-archive/manifest.json
```

备份包含私有业务记录、认证散列、展示与执行凭据；限制本地目录访问，按部署环境的受控备份存储策略加密复制。不要提交 Git、上传普通 CI 工件或公开分享。首版仅保留备份与业务审计，不设自动销毁任务；改变实际留存/删除规则另行确认业务要求。

恢复必须使用一组经过哈希核验的双库备份，先停止所有写入并备份当前状态。恢复到新隔离环境后，将 `mysql.sql` 输入该环境的 MySQL 空库，将 `checkpoint.dump` 用 `pg_restore --no-owner --no-acl --exit-on-error` 恢复至空 checkpoint 库；再运行 `checkpoint-setup` 重建受限权限，执行迁移检查，核对业务回执/消息/账本和 checkpoint 行数，最后启动同版本应用。不要只恢复其中一个数据库。

交付复验会真实恢复到本次随机 `p6_restore_*` 临时库，核对 10 张关键表后删除本次临时恢复库；原备份保留。用户运行库不被覆盖。备份来源和恢复结果在交付报告中可复核。

## 节点解释与评测

```powershell
# backend/；只读官方 checkpoint 历史，不调用模型，不冒充远端追踪
..\.venv\Scripts\python.exe -m scripts.export_graph_execution 123 --output ../artifacts/p6/session-123-nodes.json
```

输出包含图版本、输入序号、checkpoint ID、步骤和 next_nodes，可检查 parse_intents、commit_business、publish_reply 等节点的执行位置。它不含私有策略/原始提示词，也不替代 LangSmith 的真实 callback 与远端回读门槛。

确定性及真实双库回归命令见 README；协议测试和 P5 真实评测不能同时运行。完整 HTTP 交付脚本使用全新独立 Compose 项目和卷，测试失败也保留报告、服务日志和卷；每次输出目录必须新建。

CI 配置位于 `.github/workflows/ci.yml` 和 `model-evaluation.yml`。前者使用无密钥单元检查和真实双库、多进程协议回归；后者仅手动触发并绑定 `model-evaluation` 环境与账号密钥，结果绑定提交。未在本地配置远端仓库账号或触发远端 CI；本地通过的检查不能写成远端通过。

## D5 浏览器与完整应用恢复复验

在项目根目录先用当前源码构建镜像 `docker compose build api frontend`；网络需要时可按 README 设置 `DOCKER_REGISTRY=docker.m.daocloud.io`。镜像构建成功不代表交付通过。安装前端锁定依赖 `npm ci`，准备 Playwright Chromium，或在 Windows 设置 `PLAYWRIGHT_CHANNEL=msedge` 使用已安装 Edge。

在 `backend/` 显式执行（会调用真实模型；输出目录必须不存在）：

```powershell
$env:PYTHONUTF8='1'
$env:PLAYWRIGHT_CHANNEL='msedge'
..\.venv\Scripts\python.exe -m scripts.run_p6_delivery --allow-real-model --browser --output ../artifacts/predeploy/本次新目录/delivery
```

原交付环境使用 `33307/55433/18100/15174`；完整恢复环境使用 `33308/55434/18101/15176`。脚本先检查端口，使用随机 `secondhand-p6-*` Compose 项目和全新卷，不覆盖用户运行库。`--browser` 会补充生产 Worker 停止/启动与 watchdog 重启、接受后丢响应/刷新、卖家审批通知延迟、确认以及真实 Cookie 切换；随后从本次停写备份恢复到第二套空环境，先核对表数、迁移与普通/清理角色权限，再启动 API/Worker/watchdog 和浏览器验证历史及新的模型输入/关闭操作。原有真实进程中途退出故障仍由双库协议测试覆盖。

报告包括 `report.json`、`browser/report.json`、`browser/database-check.json`、截图、`restored-application/report.json` 与各 Compose 日志。模型账本保留失败、未知用量和已知费用；恢复环境账本含备份复制的调用，汇总必须按调用 ID 去重，不能将复制记录再次计费。`deployment.env`、`browser-credentials.json`、备份及原始日志仅留在本地忽略目录，不提交或上传普通 CI。失败和成功运行均保留本次卷；应用容器由脚本 `down` 收尾，禁止添加 `-v` 清掉证据。真实模型/完整恢复复验保持显式执行，不进入无收费 CI。
