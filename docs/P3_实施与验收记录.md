## 已实现能力

1. **独立审批图**：`approval:{id}:v1` 使用官方 PostgreSQL saver、动态 `interrupt` 和
   `Command(resume={event_id})`。checkpoint 保存执行位置，MySQL `approval_executions`
   只保存所有权、代次、重试和 checkpoint 关联。审批等待不占用主协商线程。
2. **决定与效力分离**：保留 PENDING / APPROVED / REJECTED / CANCELLED / EXPIRED；
   增加 NOT_APPLIED / APPLIED / INVALIDATED、effect_revision、notification_status。
   替代、撤回及关闭保留原批准时间、意见和决定，另记 invalid_reason、invalidated_at、superseded_by。
3. **卖家入口**：已有审批 API 根据记录所属 Runtime 分派。新路径核验账号归属、具体报价、
   版本、截止时间、事实与成本，使用卖家范围的请求指纹。相同请求重放，不同载荷冲突。
   同意只保存授权及 Outbox；拒绝原子完成报价拒绝和退出等待，同时建立唯一通知义务。
4. **结果应用**：审批图重新读取真实事件和决定；不能通过 resume 传入 approved=true 取得授权。
   ApplyApprovalResult 校验执行租约及当前依据，接受、效力修订、动作回执、通知和 Outbox 同事务提交。
   卖家拒绝已完成的业务效果不再重复应用。
5. **乱序与恢复**：决定早于首次启动或到达 load 与 interrupt 之间均可收尾。
   较新失效会结清先前决定事件，重复投递只读取原回执；END 后崩溃可以只完成事件确认。
   首次领取、应用、发布和 END 后真正退出子进程，再由另一进程恢复；旧租约不能提交。
6. **生命周期**：当前买家报价接受后、AGREED 前可替代或撤回；Agent 还价被替代时记为 REJECTED。
   关闭会话同步终结未决草案。AGREED/CLOSED 不因旧事件或已排队输入重新打开。
   仅关联当前报价的事件能够退出等待，旧审批不覆盖新 WAITING_APPROVAL。
7. **对账与期限**：Worker 对活跃报价按最近检查时间轮转，处理审批响应到期和报价、成本、
   政策、事实失效。及时批准不受之后审批响应截止的影响，但仍受原报价及依据期限限制。
   确认、展示和刷新重新校验依据；上下文期限取报价、成本与 30 分钟窗口的最早值。
8. **唯一通知**：审批使用 `approval:{id}:result:{effect_revision}`，与现有通知 Worker 共用发布器。
   独立通知可以在图 checkpoint 损坏时履行已提交义务，但不推进图位置或买家输入游标。
   旧结果发布为历史说明且不创建旧确认凭据；旧版本通知不会覆盖新版本投递状态。
9. **用户界面与语义**：卖家页面显示决定、效力、替代报价、响应截止和通知状态；意见修改与网络
   重试使用一致请求载荷。新提示词 `p3-intents-v1` 仅增加审批进展查询，旧版本保留供冻结输入恢复。
   进展回复在发布时重新读取状态，不让计划阶段的旧答案覆盖已提交决定。

独立图的中断和恢复遵循 [LangGraph 官方 interrupt 协议](https://docs.langchain.com/oss/python/langgraph/interrupts)，
实际行为由本仓库安装版本和跨进程集成测试验证。
