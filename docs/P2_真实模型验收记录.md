## 真实发现及修正

| 发现 | 证据与影响 | 修正及回归 |
|---|---|---|
| 否定报价误判为撤回 | 扩展集中的“我不接受900自提”被解释成 `WITHDRAW_OFFER`；增加已有报价场景后实际得到 `OFFER_WITHDRAWN`，确认是真实副作用问题 | 提示词明确拒绝与撤回的区别；程序不允许否定报价触发动作，撤回须有明确且未被否定的原文指令；保留错误模型输出的确定性回归 |
| 局部条件错误影响另一备选 | “900自提，或者如果电池至少90%就950包邮到上海”被全句条件检查拒绝，未生成备选卡片 | 共同条件仍逐项保留；仅当子句或唯一明确金额能定位备选时缩小检查范围，第二项遗漏条件仍拒绝；第一项可选择提交 |
| 模型拼接非连续引用 | v2 的共同条件备选出现不属于原文连续子串的引用，被验证器拒绝 | v3 提示词明确备选引用与条件引用分别取原文子串；不放宽原文溯源要求；无效响应仍不执行 |
| 共同条件生成错误结构 | v3 真实图有一轮将共同条件生成为额外父意图，并把条件字段放在意图顶层，导致澄清而非备选卡片；没有业务副作用 | v4 增加完整结构示例，明确条件只放在候选条款内且不能生成父报价；该输入加入扩展集后，重跑全部语义集和真实图 |
| 修改意图未提取新条款 | v4 将“行，但是得包邮”识别为修改，但 candidate=null；真实图错误复用了旧自提报价 | 报价及修改意图必须有本轮非空候选，空候选不可合并旧报价；新增两项确定性回归和真实多轮验收 |
| 提示词整体重写回退 | v5 在短回答、费用承担方、问题类型和反向条件上退步，基本集 16/20、扩展集 13/21 | 放弃重写版本，v6 从较稳定的 v4 增加明确变更/短回答规则；旧版本仅为冻结输入恢复保留 |
| 额外字段与否定作用范围 | v6/v7 仍出现额外 source_quote_full 字段；否定关闭检查也把“不买了，结束吧”误拦截 | 启用提供方 JSON Schema，保留本地校验；结构失败在原账本内最多修复一次；收窄否定词作用范围，并增加正向关闭与负向动作回归 |
| 校准标签过窄 | “不是包邮，900自提可以吗？”输出 `CHANGE_TERMS` 而原标注只允许 `PROPOSE_OFFER`，条款内容一致 | 标注允许这两个已有等价入口，与原金额纠正样例一致；单独列为标注修正，不算业务缺陷 |
| 新回归断言自身错误 | 无动作、无草案时合法返回空卡片，新测试直接调用 `.get` 失败 | 修正测试空值断言，完整图回归重新通过 |

提示词 v1～v7 的原文仍在版本映射中，旧冻结输入可继续使用其原版本；单元测试对八个版本都验证
SDK 参数和调用能力。无效响应的异常文本保持通用，不把原始输出写入异常消息；本地显式验收报告
可以保存原始响应和已知用量用于诊断。

严格结构模式依据 [阿里云结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)
核验，当前模型支持 JSON Schema。实测仍发现一次额外字段，因而不以提供方声明替代本地验证。
一次结构修复使用固定的公开校验提示，不含卖家私有策略；预留与失败调用不清零，成功产物沿用同一
账本步骤键，崩溃重放不会重复调用。两次均失败时澄清收尾。标签断言失败不触发重试。

## 遗留问题与下一步

本次未扩展既定阶段业务语义。区域成本仍为卖家维护的精确区域匹配，不接物流履约；未知事实、
未知成本、未支持承诺和无法明确解释的输入继续保存草案或澄清，不凭模型编造执行依据。

后续仍按原方案进入 **17.4 P3 审批与生命周期**，实现独立审批图、乱序事件、撤回/变更后的审批收尾、
到期与取消对账。P2 可以产生待审批报价，旧审批入口仍不能应用新图审批。P4 完整预算与追踪、
P5 独立质量评测、P6 常驻部署和清理仍是后续阶段范围；本次没有启动这些阶段或推送远端。
